# Mebel Demo

Операционная система для производства мебели на заказ: заказы, производство, склад, зарплаты, аналитика и голосовой ассистент.

## Требования

- Node.js 20+
- npm

## Установка

```bash
npm install
npm run db:seed   # демо-данные (опционально, bootstrap создаёт seed при первом запуске)
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

Продакшен: см. раздел [«Деплой на VPS»](#деплой-на-vps).

## Модули

- **Главная** — KPI, динамика заказов, воронка, склад, задачи, голосовой ассистент
- **Заказы** — воронка, карточка, этапы производства, чек-листы
- **Клиенты** — база клиентов и история заказов
- **Калькулятор** — расчёт стоимости и КП
- **Производство** — этапы цеха и загрузка
- **Склад** — остатки и движения
- **Сотрудники** — кадры, посещаемость, QR
- **Зарплаты** — начисления, авансы, штрафы
- **Задачи** — поручения и дедлайны
- **Отчёты** — отчёты сотрудников
- **Финансы** — выручка и прибыль
- **Чек-листы** — контроль по заказам
- **Аналитика** — периоды, конверсия, источники, мастера
- **Настройки** — компания, роли, график, штрафы, QR
- **Голосовой ассистент** — команды голосом / текстом
- **PWA** — установка на устройство, офлайн-оболочка (`manifest.webmanifest`, `sw.js`)
- **Приложение компании** — у каждой компании свой адрес `/c/<slug>/` и свой манифест. «Шторы Демо»: [/c/shtory-demo/](/c/shtory-demo/)

## API (основное)

- `GET /api/analytics?period=today|week|month|quarter|year`
- `GET|PATCH /api/settings`
- `GET|PATCH /api/notifications` (`{ id }` или `{ all: true }`)
- `POST /api/voice` — голосовые команды
- `POST /api/auth/login` · `POST /api/auth/logout`

## Переменные окружения

| Переменная | Описание |
|---|---|
| `AUTH_SECRET` | Секрет подписи сессий. В production обязателен, от 32 символов |
| `NEXT_PUBLIC_APP_URL` | Публичный адрес (`https://os.example.kz`), используется в проверке Origin |
| `INITIAL_OWNER_EMAIL` / `INITIAL_OWNER_PASSWORD` / `INITIAL_OWNER_NAME` | Первый владелец. Создаётся при старте production, если активного OWNER нет. Пароль от 12 символов |
| `ALLOW_DEMO_ACCOUNTS` | `true` оставляет демо-аккаунты активными и показывает быстрый вход (в production держать `false`) |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | Ключи push-уведомлений. Сгенерировать один раз: `npx web-push generate-vapid-keys`. Без них push отключён, уведомления остаются в колокольчике |
| `VAPID_SUBJECT` | Контакт для push-сервисов: `mailto:admin@домен` |

## Деплой на VPS

1. Подготовить `.env` на сервере:
   ```bash
   NODE_ENV=production
   AUTH_SECRET=$(openssl rand -base64 48)
   NEXT_PUBLIC_APP_URL=https://os.example.kz
   ALLOW_DEMO_ACCOUNTS=false
   INITIAL_OWNER_EMAIL=owner@example.kz
   INITIAL_OWNER_PASSWORD=<длинный пароль>
   INITIAL_OWNER_NAME="Имя Фамилия"
   ```
   Без корректного `AUTH_SECRET` и владельца приложение не стартует. После первого входа
   владельца переменные `INITIAL_OWNER_*` можно удалить.
2. Сборка и запуск: `npm ci && npm run build && npm start` под отдельным пользователем
   без root (pm2/systemd).
3. nginx перед Node:
   - TLS (Let's Encrypt) и редирект с HTTP на HTTPS;
   - `client_max_body_size 20m;`
   - `proxy_set_header Host $host;`, `X-Forwarded-For $proxy_add_x_forwarded_for;`,
     `X-Forwarded-Proto $scheme;` (по `X-Forwarded-For` работает лимит попыток входа).
4. Данные: `chmod 700 data` (владелец — пользователь процесса). Ежедневный бэкап
   `data/mebeldemo.json` и `data/uploads`.
5. Проверить, что секреты и данные не попадали в git: `git log --all -- .env data`.
6. Отдельные приложения компаний не требуют новых переменных окружения и отдельной базы.
   После выкладки откройте `https://<ваш-домен>/c/shtory-demo/` и установите его на телефон.
   Замеры калькулятора пишутся в тот же `data/mebeldemo.json` (поле `clientMeasurements`,
   создаётся само, если его ещё нет). Фото замеров лежат в `data/uploads/<companyId>/measurement/`.
   Каталог `data/` при FTP-деплое не перезаписывается. Миграцию вручную запускать не нужно.

Защита: сессии 24 часа с проверкой пользователя по базе на каждый запрос, переключение
компаний только для OWNER/ADMIN, лимит 5 неудачных входов за 15 минут на IP и email
(в памяти процесса, рассчитан на один инстанс), проверка Origin для изменяющих
API-запросов, CSP и прочие заголовки безопасности.

## Деплой по FTP (Plesk)

Текущий сервер обновляется скриптом `npm run deploy`. Он собирает автономный бандл `./deploy` и заливает его по FTPS. Каталог `data/` и файлы `.env` скрипт не заливает и не удаляет. Миграции применяются сами при первом запросе после рестарта. Перед ними база копируется в `data/backups/mebeldemo-<дата>.json`. Выполненные миграции записываются в поле `migrations`, повторно они не запускаются.

1. На сервере, до выкладки, скопируйте в безопасное место `data/mebeldemo.json` и каталог `data/uploads`.
2. В окружении Node.js в Plesk оставьте уже заданные переменные. Менять их для этой выкладки не нужно:
   - `NODE_ENV=production`
   - `AUTH_SECRET` (тот же секрет, что сейчас: новый секрет разлогинит всех)
   - `NEXT_PUBLIC_APP_URL=https://<домен>`
   - `NEXT_PUBLIC_DEMO_LOGIN=false`
   - новые: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (значения из локального `.deploy.env`; без них push не отправляется)
3. На машине, с которой идёт выкладка, в корне репозитория:
   ```bash
   git fetch origin
   git checkout cursor/atelier-company-pwa-a600
   npm ci
   ```
   Если `.deploy.env` ещё нет, скопируйте `.deploy.env.example` и заполните `FTP_HOST`, `FTP_USER`, `FTP_PASS`, `FTP_DIR` (каталог, где лежит `server.js`).
   В `.env` этой машины на время сборки задайте тот же `NEXT_PUBLIC_APP_URL`, что на сервере: Next вшивает его в клиентский бандл.
4. Запустите `npm run deploy`. Скрипт соберёт проект, зальёт файлы из `./deploy` и запишет на сервере `tmp/restart.txt`, чтобы Passenger перезапустил приложение.
5. Если процесс не подхватил новую сборку, в Plesk перезапустите Node.js-приложение.
6. Откройте `https://<домен>/c/shtory-demo/` и войдите по логину сотрудника «Шторы Демо». Фото замеров появятся в `data/uploads/<companyId>/measurement/<id>/`.

Не заливайте на сервер локальный каталог `data/` и не подменяйте серверный `.env`.

## Приложение «Шторы Демо»

Адрес для установки: `https://<ваш-домен>/c/shtory-demo/`

Это отдельное приложение: своё имя на домашнем экране, без переключателя компаний.
Общая система владельца по-прежнему открывается с `/`.

На iPhone страница открывается в Safari: «Поделиться» → «На экран Домой».
На Android в Chrome: меню → «Установить приложение» или «Добавить на главный экран».
Нужен уже настроенный HTTPS.

стартовые пароли выдаются владельцу отдельно, их стоит сменить в «Настройки → Сотрудники и доступ».

или выключает отделы и модули (нет / просмотр / редактирование). Права проверяются на сервере
при каждом запросе, владельца ограничить нельзя.

### Цех и статусы

Статусы заказа: «Расчёт» (черновик калькулятора) → «Ожидает принятия в работу» → «В работе»
→ «Завершён», плюс «Отменён». Каждая смена пишется в историю: кто, когда, какой статус.

1. Менеджер в калькуляторе нажимает «Заказ в пошив в цех»: заказ сохраняется, швеи получают уведомление.
2. Швея в разделе «Цех» нажимает «Принять в работу». Принять может только одна: вторая
   получает ответ «Заказ уже принят» с именем и временем. Кемаль получает уведомление.
3. Швея или руководитель нажимает «Завершить».

### Себестоимость и финансы

«Себестоимость»: выбрать заказ, расходы подтягиваются из калькулятора (материалы и работа,
включая пошив), их можно править, добавлять доставку и свои категории. Правка фактических сумм
не меняет расчёт калькулятора, повторная синхронизация не создаёт дублей.

«Финансы»: сумма заказов, все расходы, чистая прибыль и маржа за период (месяц, квартал, год,
произвольный) и по каждому заказу. Черновики и отменённые заказы не учитываются.

### Push-уведомления

Работают на Android, компьютере и iPhone (iOS 16.4+, только из приложения на экране «Домой»).
Включение: колокольчик → «Включить» или «Настройки» → «Push-уведомления» → «Включить», там же
кнопка «Отправить тест». Если доступ запрещён, на этом же экране показана инструкция для
вашего устройства. При выходе из учётной записи устройство отписывается.

### Тестовые данные

Демо-сотрудники, клиенты и заказы «Шторы Демо» удаляются миграцией
`2026-10-atelier-purge-demo`. Записи с «тест», «demo», «e2e» в названии показываются в
«Настройки → Тестовые данные» и удаляются только после подтверждения, с резервной копией.
