# Electro Demo CRM

CRM и складской учёт для Electro Demo (электротовары и кабель, Казахстан): заявки, отгрузки, приёмки, остатки, долги, прайсы и КП, задачи и воронка, финансы, зарплата, аналитика. PWA: ставится на телефон, работает с мобильной навигацией, push-уведомлениями и офлайн-страницей.

Интерфейс на русском, деньги в тенге (₸), часовой пояс Asia/Almaty.

## Быстрый старт (локально, без Docker)

Нужен Node.js 22+ (проверено на 24). Если `DATABASE_URL` не задан, используется встроенная PGlite — настоящий Postgres в WASM, данные в `./.data/pglite`.

```bash
npm install
```
```bash
cp .env.example .env.local
```
```bash
npm run setup
```
```bash
npm run dev
```

`npm run setup` применяет миграции и наполняет базу демо-данными. Временные пароли сотрудников записываются в `.data/initial-passwords.txt`; при первом входе каждый задаёт свой пароль.

| Логин | Сотрудник | Роль |
|---|---|---|
| `director` | Директор | владелец, полный доступ |
| `accountant` | Асель | учёт, бухгалтерия, финансы, зарплата |
| `sales1` | Данияр | продажи (рынки, базар) |
| `sales2` | Арман | продажи (розница) |
| `picker` | Тимур | сборщик, стажёр |

Полезные команды: `npm test` (тесты), `npm run lint` (проверка типов), `npm run db:reset` (пересоздать локальную БД), `npm run vapid` (ключи Web Push).

## Docker (продакшен)

```bash
cp .env.example .env
```
```bash
docker compose up -d --build
```

Поднимаются `db` (PostgreSQL 17), одноразовый `migrate` (миграции + seed, если база пустая) и `app` на порту 3000. Временные пароли: `docker compose logs migrate`. Файлы вложений лежат в томе `uploads`, база — в `pgdata`. Проверка живости: `GET /api/health`.

Перед запуском в `.env` обязательно задайте `APP_SECRET` (длинная случайная строка), `APP_URL` (публичный адрес, нужен для ссылок на КП/акты и push) и при необходимости `POSTGRES_PASSWORD`. Перед приложением нужен HTTPS (nginx/Caddy) — без него не работают push и установка PWA.

Резервная копия базы: `docker compose exec db pg_dump -U demo -Fc demo > backup.dump`. Выгрузка данных в JSON — «Настройки → Резервная копия».

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | PostgreSQL. Пусто — PGlite в `./.data/pglite` |
| `APP_URL` | Публичный адрес приложения |
| `APP_SECRET` | Подпись публичных ссылок (акты сверки, прайсы) |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | Web Push (`npm run vapid`) |
| `STORAGE_DRIVER`, `STORAGE_LOCAL_DIR` | Хранилище файлов: `local` (папка) или `s3` (реализуйте драйвер в `src/lib/storage.ts`) |
| `ANTHROPIC_API_KEY` | Распознавание PDF/фото накладных при приёмке (без ключа работает разбор вставленного текста) |
| `WHATSAPP_PROVIDER` | Пусто — заглушка (ссылка wa.me) |
| `ASSISTANT_PROVIDER` | Пусто — локальная заглушка ассистента |
| `CRON_SECRET` | Внешний запуск проверок: `POST /api/cron` с заголовком `x-cron-secret` |
| `DISABLE_SCHEDULER` | `1` — выключить встроенный планировщик (если инстансов несколько) |

## Мгновенный поиск

Поиск товаров, контрагентов, сотрудников и папок работает **на устройстве**, без запроса к серверу на каждую букву.

- **Индекс** строит Web Worker (`src/lib/search/worker.ts`) из ответа `GET /api/index`. Ответ уже отфильтрован по правам: без «Видеть закупочные цены» закупочный тип цены и его значения в индекс не попадают (проверка — `tests/search-perm.test.ts`).
- **Кэш** — IndexedDB (`demo-search`, ключ на пользователя; чужие ключи удаляются, на странице входа кэш стирается). Открытие страницы мгновенное, работает офлайн.
- **Синхронизация** — дельта по `updatedAt` (`?since=`): при фокусе вкладки, возврате сети, раз в минуту и сразу после любого сохранения (`useRun` → `notifyDataChanged`). Смена прав меняет `permKey` → полная перезагрузка индекса.
- **Движок** — свой (`src/lib/search/engine.ts`, `text.ts`), а не Fuse/MiniSearch/FlexSearch. Причина: нужны правила, которых нет в готовых библиотеках «из коробки» — неверная раскладка (`rf,tkm` → кабель), транслит и смешанные алфавиты, `х/x` и `,/.` в размерах (`ввг 3х2,5`), аббревиатуры по первым буквам (`кб`), одна опечатка на слово от 4 букв, синонимы владельца и ранжирование по продажам, остаткам и истории клиента. Fuse медленный на 5000+ записей (линейный нечёткий перебор), MiniSearch/FlexSearch не знают раскладок и плохо ранжируют префикс против подстроки. Свой движок — ~400 строк без зависимостей.
- **Скорость** — без debounce. 5000 товаров: построение индекса ≈ 80 мс, поиск p50 < 1 мс, p95 ≈ 3 мс (`tests/search.test.ts`). В браузере: `await __demoSearch.bench(5000)`, отклик «клавиша → отрисовка» — `__demoSearchPerf`.
- **Ранжирование** — точное/префикс > синоним > подстрока > опечатка/раскладка; затем «брал этот клиент», продажи за 180 дней, наличие.
- **Синонимы** — «Настройки → Параметры → Синонимы поиска» (только владелец).
- **Резерв** — пока индекс не загрузился в первый раз, работает серверный `GET /api/search`.

## Права доступа

Каждому сотруднику для каждого модуля задаётся уровень «нет / просмотр / полный» и флаги: видеть закупочные цены, видеть прибыль и маржу, видеть все зарплаты, удалять документы, права по зарплате. Владелец имеет полный доступ.

Права проверяются в сервисах (`src/modules/*/service.ts`), а не в интерфейсе, поэтому одинаково действуют для страниц, REST API и MCP. Закупочные цены и маржа без флага не попадают в ответ сервера вообще. API-токен получает пересечение своих прав и прав сотрудника, который его выпустил.

## REST API и MCP

Токен выпускается в «Настройки → API и MCP» и показывается один раз; в базе хранится только SHA-256. Для разработки можно выпустить токен владельца из консоли: `npx tsx --import ./scripts/stub-server-only.mjs scripts/api-token.ts "Имя"`.

- **REST:** `GET /api/v1/products?q=ввг`, `POST /api/v1/orders`, `POST /api/v1/leads` и др. Описание — `/api/v1/openapi.json` (OpenAPI 3.1). Ответ `{ data }` или `{ error }`, лимит 120 запросов в минуту на токен.
- **MCP:** `POST /api/mcp` (Streamable HTTP, JSON-RPC, без сессий). Инструменты: поиск товаров, товары ниже минимума, контрагенты, долги, заявки, мои задачи, создание задачи и лида, сводка продаж. Набор инструментов зависит от прав токена, каждый вызов пишется в журнал («Настройки → API и MCP»).

```bash
curl -H "Authorization: Bearer demo_..." "http://localhost:3000/api/v1/debts"
```

**Вебхуки** («Настройки → Вебхуки»): POST JSON `{ event, data, sentAt }` на события заявок, отгрузок, оплат, приёмок, лидов, задач и отрицательного остатка. Подпись: заголовок `X-DEMO-Signature: sha256=<hex>` — HMAC-SHA256 секрета от строки `<X-DEMO-Timestamp>.<тело>`.

## Технические соглашения

- Next.js 16 (App Router), React 19, TypeScript, Tailwind 4, Drizzle ORM, PostgreSQL / PGlite, React Query.
- Деньги — целые тиыны (1 ₸ = 100), проценты ставок — базисные пункты. Документы удаляются мягко (`deleted_at`).
- Сессии в httpOnly-cookie, пароли bcrypt, ограничение попыток входа, валидация zod на каждом действии и маршруте, аудит изменений.
- PDF формируются на сервере (`@react-pdf/renderer`) шрифтом Noto Sans из `assets/fonts` — в нём есть кириллица, казахские буквы (ә, ғ, қ, ң, ө, ұ, ү, һ, і) и знак ₸.
- Фоновые проверки (сроки задач, зависшие лиды, напоминания) — `src/instrumentation.ts`, каждые 5 минут.
- Структура: `src/modules/<модуль>/` — сервис (бизнес-логика и права) и серверные действия; `src/app/` — страницы и маршруты; `src/components/` — UI-кит, графики, канбан.

### Как подключить заглушки

- **WhatsApp:** реализуйте `WhatsAppProvider` (`sendText`, `sendDocument`) в `src/modules/whatsapp/provider.ts` и выберите его в `getWhatsApp()` по `WHATSAPP_PROVIDER`.
- **Ассистент:** реализуйте `AssistantProvider.reply()` в `src/modules/assistant/provider.ts`. Описания инструментов берутся из `toolsFor(p)` и `toolJsonSchema(t)`, вызовы — через `runTool(db, p, name, args)`; права соблюдаются автоматически.

## Схема данных (ER)

```
users ─┬─< sessions, push_subscriptions, notifications
       ├─< pay_schemes, payroll_accruals, payroll_adjustments, timesheet, payroll_advances, payroll_payouts
       ├─< api_tokens ─< mcp_call_log
       └─ (manager/author/assignee) → counterparties, orders, tasks, leads

folders ─< products ─< product_prices >─ price_types
                    └─< price_history (price_batches — массовые изменения с откатом)

counterparties (клиент | поставщик | оба; сегмент; лимит долга; теги)
   ├─< orders ─< order_items >─ products
   │     ├── status → order_statuses;  ─< order_status_history
   │     └─< shipments (отгрузка | возврат) ─< shipment_items >─ products
   ├─< receipts (приёмки) ─< receipt_items >─ products
   ├─< payments (in | out) → cash_accounts; ссылки на order / shipment / receipt
   └─< quotes (КП, шаблоны) ─< quote_items

warehouses ─< shipments, receipts, inventories ─< inventory_items
cash_accounts ─< fin_transactions >─ fin_categories        (ДДС)

task_stages ─< tasks ─< task_comments
lead_stages ─< leads ─< lead_events
notes, files, settings (key → JSON), counters (нумерация документов),
audit_log, webhooks, payroll_periods, accrual_rules, kpi_targets
```

Остаток товара не хранится, а считается: проведённые приёмки − отгрузки + возвраты ± инвентаризации (`src/modules/stock/queries.ts`). Долг контрагента — сумма отгрузок минус возвраты и оплаты (`balancesSql`). Себестоимость продажи фиксируется в строке отгрузки на момент проведения.
